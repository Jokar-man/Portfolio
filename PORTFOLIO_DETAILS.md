# Portfolio Website — Detailed Status

A snapshot of what exists in this repo today: how the site is built, what each page does, what visual/interaction effects are implemented, what project data is loaded, and what's still a placeholder. Generated by reading the source directly (not from memory) — treat this as accurate as of the last commit (`dd53b69`).

## 1. Tech stack & build

- **Vite** (vanilla JS, no framework) — two HTML entry points built as a multi-page app: [vite.config.js](vite.config.js)
  - `index.html` → `src/main-globe.js` — the **Projects** page (interactive globe/map)
  - `profile.html` → `src/main-profile.js` — the **Profile** page (CV)
- **Three.js** `^0.169.0` is the only runtime dependency — used for WebGL rendering, `OrbitControls`, and the post-processing bloom pipeline (`EffectComposer`, `RenderPass`, `UnrealBloomPass`).
- No component framework, no router — pages are plain DOM built with `innerHTML`/`createElement` in JS modules.
- Deploys to **GitHub Pages** via [.github/workflows/deploy.yml](.github/workflows/deploy.yml) on every push to `main` (`npm ci && npm run build`, publishes `dist/`). Site base path is `/Portfolio/`.
- Font: Google Fonts **Inter** (400/500/600/700), loaded in both HTML files.

## 3. Projects page (`index.html`) — the globe/map experience

This is the centerpiece of the site: [src/globe/Globe.js](src/globe/Globe.js) orchestrates a state machine with four states — `map` → `transitioning` → `detail` | `network`.

### 3.1 Default view: flat equirectangular map

- The site **opens directly on a flat map**, not a rotating globe (there's no standalone "spinning globe" landing view — that only appears in "Visualize" mode).
- A **shader-based point cloud** (`THREE.Points` + custom GLSL, [src/globe/pointsShader.js](src/globe/pointsShader.js)) renders per-country dots loaded from `public/image/ccvi.csv` (lat/lon/iso3 data). Each point:
  - Gets a deterministic color hue derived by hashing its ISO3 country code ([loadCsv.js](src/globe/loadCsv.js) `hashToUnit`), so each country has a stable, consistent tint every load.
  - Is drawn as a soft anti-aliased circle in the fragment shader (`smoothstep` falloff, alpha-blended, `depthWrite: false`).
  - Point size is scaled by device pixel ratio so it looks correct on Retina/high-DPI screens.
- Every point (and every project marker) is authored with **two positions** — a sphere position and a flat equirectangular position — and a single `uMorph` uniform (0 = flat, 1 = sphere) lets the vertex shader `mix()` between them. This is what drives the map↔globe morph transition.
- **17 project markers** (small red spheres, `#ff6b6b`) sit on the map at real-world lat/lon. Each has a **DOM "chip"** (thumbnail + title + affiliation/scope) floating above it — real HTML buttons, not raycast targets, so clicks aren't swallowed by `OrbitControls`.
  - Chips **auto-resolve overlaps**: markers are projected to screen space every frame, sorted left-to-right, and any chip that would collide with an already-placed one is bumped up/down in alternating steps — this stops geographically clustered projects (e.g. multiple in Barcelona) from stacking invisibly on top of each other.
  - Mouse wheel scrolling over a chip is manually re-dispatched to the canvas, because `OrbitControls`' zoom listener is bound to the canvas and a chip sitting on top of it would otherwise eat the scroll event.
- Map interaction: pan via left-drag (remapped from `OrbitControls`' default rotate), zoom via wheel, no rotation.

### 3.2 Clicking a project marker → Detail view

- Camera **dollies in** on the marker (`dollyToMarker` in [MapTransition.js](src/globe/MapTransition.js), 1200ms eased) and a **detail panel** slides in ([ProjectCard.js](src/globe/ProjectCard.js)):
  - Chamfered/clipped-corner card (CSS `clip-path` hexagon-style corners), dark translucent background, scale+fade-in transition.
  - Shows: hero image (or a lettered placeholder tile if no image yet), title, location + affiliation/scope line, category tag pills, and a description paragraph.
  - Close button dollies the camera back out to the full map view.
- Easing throughout the app is a shared `easeInOutCubic` tween helper ([tween.js](src/shared/utils/tween.js)) — nothing snaps instantly.

### 3.3 "Visualize ✦" button → Network mode

The most complex feature, in [src/globe/NetworkOverlay.js](src/globe/NetworkOverlay.js):

- Camera flies out and the map **morphs into a rotating 3D globe** (`transitionToGlobe`), auto-rotating continuously (faster when nothing is selected, slower once a topic/tool is picked).
- **Post-processing bloom** is added (`UnrealBloomPass`) — this view only, giving the glowing/HDR look; the flat map/detail views render without bloom.
- Two HUD anchor rails, laid out as fixed DOM elements:
  - **Topics** (top-left): Urban Computation, Architecture, Geospatial Research, AI for Built Environment, Connections, Design Engineering, Software.
  - **Tools** (bottom-right): Python, Rhino/Grasshopper, QGIS/ArcGIS, Google Earth Engine, N8N/RAG Agents, Three.js/D3.js, Pandas/Scikit-learn.
  - Topic↔project and tool↔project links are computed from `projects.json` categories via [networkData.js](src/globe/networkData.js) — tool links are **inferred heuristically from category tags** (there's no real per-project tool list yet; see §5).
- Hovering or clicking a topic/tool:
  - Draws **glowing amber Bézier "thread" curves** (additive blending, `THREE.AdditiveBlending`, low individual opacity so overlapping threads brighten) from the anchor's screen position out to every linked project marker on the globe, with a perpendicular sine "wobble" so threads look woven rather than straight, and multiple jittered sub-threads per link based on a `weight`.
  - Threads are recomputed every frame from live marker world-position, so they keep tracking correctly as the globe spins underneath.
  - Matching project markers **scale up (×1.8)** and get a floating name label; non-matching markers hide.
  - Selecting **both** a topic and a tool narrows to their intersection and shows a combo label ("Topic × Tool → Project A, Project B" or a "no match" message) at the top of the screen.
  - Anchors are click-**lockable** (stay selected without hovering) as well as hover-previewable.
- A "Pause Rotation" button freezes the auto-rotation for easier reading.
- "← Back to Map" reverses everything: unwinds the globe's spin, morphs back to flat, flies the camera back to the map framing.

## 6. Known gaps / inconsistencies

- **11 of 17 projects** are placeholder-only (`"Details coming soon."`, no image) — see the table in §3.4.
- **Tool tags in Network mode are inferred, not real data.** [networkData.js](src/globe/networkData.js) explicitly comments that `inferToolIds` is a placeholder mapping from category → tool, "replace... once that data exists." Per-project tool lists don't exist yet.
- **`data/anchor-bubble-visualization-spec.md`** describes a different, more elaborate design (circle-packed "bubble" nodes sized by percentage, coordinate readouts, hand-rolled collision layout) than what's actually built. The live `NetworkOverlay` uses fixed two-column topic/tool rails and Bézier threads to markers on a globe — it's inspired by that spec but is a simplified implementation, not a 1:1 build of it.
- **Unused images**: `public/image/Architecture/` and `public/image/Urban Computation/` contain many files not referenced by any project in `projects.json` — e.g. Capella School District renders/plans, GV1 detail shots, DNL plan/section drawings, Heat Archipelagos GIFs/renders, Open City process GIFs, LA fire segmentation/website shots, Rundu app maps/pedestrian-sim GIFs, a Covid Python plot. These look like material ready to be attached to project entries but aren't wired in yet.
- **Projects referenced in the CV but missing from the map**: `main-profile.js`'s Experience section mentions "Heat Archipelagos" and "Capella School District" as delivered work — neither has a corresponding entry in `data/projects.json`, so they don't appear on the Projects page at all.
- **Profile page content is explicitly marked placeholder** in the source: the Experience timeline has a literal `"Placeholder timeline — replace with full work history."` note, and Education has a stub entry with `"(add institution)"`.
- **No standalone "spinning globe" landing state** — despite `Globe.js` naming and a `globeCameraPos`, globe view is currently reachable only through "Visualize" (network mode), never as an idle/default view.
